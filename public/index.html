01 / WORKFLOW

A controlled experiment.

Choose a task and environment seed. Run the reference agent with a fault, then rerun in a fresh environment with the selected repair policies. Finally, run both policy sets on the matched clean task.

Each execution produces an inspectable trace: task, tools and their actual fixture outputs, policy interventions, structured decision, and deterministic field checks. All delivery actions are recorded only inside an isolated in-memory fixture.

02 / OBJECTIVE

The smallest repair that meets the constraints.

minimize |policies|
then minimize total suite tool calls

Subject to: the chosen task passes (or all fault cases pass when selected), clean controls have zero regressions, and the extra tool calls on the selected case stay within the budget.

Five Boolean policies produce 2⁵ = 32 subsets. REWIND enumerates each subset against 12 seeded fault cases and 12 matched clean controls. Ties are resolved deterministically. “Always abstain” demonstrates why a safe refusal alone is not task success.

03 / EXECUTION MODES

Reference and live mean different things.

Reference: a deliberately fallible, rule-based agent whose source is available in the project. Its behavior is fully reproducible. Search results describe this agent and these synthetic tasks.

Live Gemini: a real API request makes the final structured decision from the tool evidence. Enabled policies control evidence retrieval and enforce the recipient boundary. A comparison makes up to four provider requests. Live mode uses a fixed tool-acquisition harness, not autonomous tool planning.

Your key stays in page memory and is sent only to this server and Google's API. It is never saved in browser history, exports, logs, or a server database. Refreshing the page clears it. Provider usage may incur charges. Seeded fixtures do not make model generations deterministic.

04 / AGENT INTERFACE

A lab other agents can call.

The stateless Streamable HTTP endpoint /mcp exposes rewind_run, rewind_compare, rewind_search, and rewind_suite. It implements the MCP 2025-03-26 protocol subset for tools; it does not connect to arbitrary external MCP servers.

05 / LIMITATIONS

Evidence, with boundaries.

These four task families are synthetic and intentionally small. Passing them is not proof of general safety, real-world reliability, or benchmark superiority. Policies and fixtures were designed together; successful repairs are expected behavior, not an independently validated research finding.

Scoring checks exact decision fields. It does not use a subjective model judge. Fixture seeds vary numeric task values, not adversarial wording. Causal effects are specific to the controlled environment; this is not general causal identification.

Export hashes detect accidental changes, not forgery: they are digests, not signatures. The public demo has a global request cap. Experiment history is browser-local and can disappear if browser data is cleared.
